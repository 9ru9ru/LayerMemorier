# LayerMemorier spec

작성 2026-09-15. 원 요청은 저장소 루트 `기획.txt`.

## 0. 한 줄 요약

포토샵 2020용 CEP 패널. PSD 안의 레이어에 "어느 배리에이션에 속하는지"를 마킹해 두면, 모든 배리에이션 조합을 자동으로 켜고 끄며 PNG로 내보낸다. 마킹과 카테고리 구성은 PSD 안(XMP)에 저장되고, 카테고리 구성은 프리셋으로 다른 PSD에서도 재사용한다.

## 1. 목표와 비목표

목표:

- 카테고리(의상·옷·가슴·보태배·프레임 번호 등)를 정의하고 값 목록을 만든다. 만든 구성은 프리셋으로 저장해 다른 파일에서 다시 쓴다.
- 레이어(그룹 포함)마다 카테고리 값을 마킹한다. 패널의 레이어 트리에서 색 배지로 한눈에 구분된다. 옵션으로 포토샵 네이티브 레이어 색도 같이 바꾼다.
- 배리에이션 전체(카테고리 값의 데카르트 곱)를 한 번에 PNG-24로 내보낸다. 파일명 순서·폴더 묶기 단계를 지정한다.
- 개발자가 포토샵을 직접 열어 보지 않고도 자동으로 검증할 수 있어야 한다 (§11).

비목표 (이번 범위 밖):

- macOS, 포토샵 2021 이상(UXP), CEP 10 이상 전용 기능.
- PNG-24 이외의 출력 형식, 트림(레이어 크기로 자르기), 리사이즈.
- 하위 카테고리 값이 상위 값에 따라 달라지는 구조 (2026-09-15 결정: 순서만 의미 있음).
- 레이어 이름을 읽어 자동으로 마킹하는 기능 (향후 §13).
- 마킹 작업의 되돌리기(undo). 마킹은 포토샵 히스토리에 잡히지 않는다.

## 2. 용어

| 용어 | 뜻 | 예 |
|---|---|---|
| 카테고리 | 배리에이션을 나누는 축 하나 | 의상, 옷, 가슴, 보태배, 프레임 |
| 값 | 카테고리가 가질 수 있는 상태 하나 | 옷 = 0, 1, 2, 3 |
| 라벨 | 값이 파일명에 들어갈 때 쓰는 문자열. 빈 문자열이면 생략 | 옷0, 기본의상, (빈 문자열) |
| 배리에이션 | 모든 카테고리에서 값을 하나씩 고른 조합 | 기본의상 × 옷1 × 가슴0 × 보태배0 × 3 |
| 마크 | 레이어 하나에 붙은 "카테고리 → 값 집합" 정보 | 옷 ∈ {0, 1}, 가슴 ∈ {0} |
| 프리셋 | 카테고리 목록의 묶음. 파일과 무관하게 저장 | "프시케 포즈" |
| 문서 데이터 | PSD 한 개에 저장되는 카테고리 사본 + 마크 + 출력 설정 | |
| 출력명 | 파일명 맨 앞에 붙는 이름 | 알싸기 |

## 3. 플랫폼과 제약

- 포토샵 2020 21.0.2 (Windows). 런타임은 CEP 9 (Chromium 63, ES2017 사용 가능). UXP 없음.
- 호스트 스크립트는 ExtendScript (ES3). `JSON`이 없으므로 json2.js를 포함한다. `let`/`const`/화살표 함수 사용 불가.
- 패널과 호스트는 문자열로만 통신한다 (`csInterface.evalScript(문자열, 콜백)`). 모든 입출력은 JSON 문자열.
- 서명 없는 익스텐션이므로 각 PC에서 레지스트리 `HKCU\SOFTWARE\Adobe\CSXS.9\PlayerDebugMode = "1"`을 한 번 설정해야 한다.
- 익스텐션 설치 위치는 `%APPDATA%\Adobe\CEP\extensions\LayerMemorier`. 개발 중에는 저장소 폴더로 향하는 정션(junction)을 만든다.

## 4. 데이터 모델

### 4.1 카테고리

```json
{
  "id": "c_9f3a",
  "name": "옷",
  "color": "orange",
  "labelFormat": "{c}{v}",
  "folder": false,
  "values": [
    { "id": "v_1a2b", "name": "0", "label": "0" },
    { "id": "v_3c4d", "name": "1", "label": "1" }
  ]
}
```

- `id`는 생성 시 임의 문자열. 이름을 바꿔도 마크가 깨지지 않도록 이름 대신 id로 참조한다.
- `color`는 배지 색. `red, orange, yellow, green, blue, violet, gray` 7종. 새 카테고리는 아직 안 쓴 색을 순서대로 받는다. 8번째부터는 `gray`.
- `labelFormat`은 `{v}`, `{c}{v}`, `{c}_{v}` 셋 중 하나. `{c}`는 카테고리 이름, `{v}`는 값 라벨. 값 라벨이 빈 문자열이면 형식과 무관하게 토큰 전체를 생략한다.
- `folder`가 true면 이 카테고리 단계에서 폴더를 만든다 (§5.4).
- 값의 `name`은 패널 표시용, `label`은 파일명용. 기본값은 둘이 같다. "'기본'이면 파일명에서 생략" 같은 규칙은 label을 빈 문자열로 두어 만든다.
- 넘버링 카테고리는 별도 타입이 아니다. 카테고리 편집 UI에 "범위로 값 만들기 (시작, 끝)" 버튼이 있어 값 `1..5`를 한 번에 만든다.

### 4.2 프리셋 파일

경로 `%APPDATA%\LayerMemorier\presets.json`. 패널이 `cep.fs`로 읽고 쓴다.

```json
{
  "version": 1,
  "presets": [
    { "id": "p_1", "name": "프시케 포즈", "categories": [ ...카테고리 배열... ] }
  ]
}
```

프리셋을 문서에 적용하면 카테고리 배열이 문서 데이터로 **복사**된다. 이후 문서에서 고쳐도 프리셋은 바뀌지 않는다. 반대로 "현재 카테고리를 프리셋으로 저장"으로 문서 → 프리셋 복사가 된다. 프리셋을 적용할 때 문서에 이미 마크가 있으면 경고 후 마크를 전부 지운다 (카테고리 id가 달라져 매칭이 안 됨).

### 4.3 문서 데이터

PSD의 XMP 메타데이터에 저장. 네임스페이스 `http://layermemorier.local/1.0/`, 접두사 `lm`, 속성 `lm:data` 하나에 JSON 문자열 전체를 넣는다. ExtendScript의 `AdobeXMPScript`로 읽고 쓴다. `app.activeDocument.xmpMetadata.rawData`에 쓰면 문서가 수정 상태가 되고, **PSD를 저장해야 디스크에 남는다.**

```json
{
  "version": 1,
  "baseName": "알싸기",
  "delimiter": "_",
  "destination": "D:/export/알싸기",
  "nativeColor": true,
  "categories": [ ...카테고리 배열. 배열 순서 = 파일명 순서 = 폴더 순서... ],
  "marks": {
    "1234": { "c_9f3a": ["v_1a2b", "v_3c4d"] },
    "1290": { "c_9f3a": ["v_1a2b"], "c_77aa": ["v_00ff"] }
  },
  "excluded": [
    { "c_9f3a": "v_3c4d", "c_77aa": "v_00ff" }
  ]
}
```

- `marks`의 키는 포토샵 `layerID` (문자열). layerID는 PSD에 저장되어 파일을 닫았다 열어도 유지된다. 레이어를 다른 문서로 복사하면 새 id를 받으므로 마크는 따라가지 않는다.
- `excluded`는 부분 조합 목록. 항목의 모든 (카테고리 → 값) 쌍을 만족하는 배리에이션은 제외된다.
- `nativeColor`가 true면 마크할 때 포토샵 네이티브 레이어 색도 바꾼다 (§6.2).

## 5. 규칙 (core 로직)

이 절의 규칙은 전부 순수 함수로 구현하고 Node 단위 테스트로 고정한다 (§11.1).

### 5.1 배리에이션 열거

- 입력: 카테고리 배열, 제외 목록, (선택) 카테고리별 포함 값 집합.
- 출력: 배리에이션 배열. 각 배리에이션은 `{ [categoryId]: valueId }`.
- 순서: 첫 카테고리가 가장 느리게 변하고 마지막 카테고리가 가장 빠르게 변한다 (중첩 for 루프 순서). 값 순서는 배열 순서.
- 값이 0개인 카테고리가 있으면 배리에이션은 0개. 카테고리가 0개면 배리에이션은 1개(빈 조합)이며 파일명은 출력명만이다.
- 포함 값 집합이 주어진 카테고리는 그 값만 쓴다 (부분 출력, §6.3). 세션에서만 유지하고 저장하지 않는다.
- 제외 목록 항목과 모든 쌍이 일치하는 배리에이션은 뺀다.

### 5.2 레이어 가시성 판정

- 입력: 레이어 마크 `{ [categoryId]: valueId[] }`, 배리에이션.
- 마크가 비어 있으면 결과는 `null` (건드리지 않음).
- 마크된 모든 카테고리에 대해 배리에이션 값이 그 집합에 있으면 `true`, 하나라도 없으면 `false`.
- 마크에 있는 카테고리가 현재 카테고리 목록에 없으면 그 항목은 무시한다 (남은 항목으로만 판정). 값 id가 카테고리에 없으면 그 값은 집합에서 없는 것으로 본다. 두 경우 모두 패널이 경고로 보여 준다 (§9).
- 그룹 레이어도 같은 규칙. 그룹이 꺼지면 자식은 포토샵 동작대로 안 보인다. 그룹이 켜지면 자식은 각자 판정.

### 5.3 파일명

- 토큰 = 카테고리 배열 순서대로, 각 카테고리의 값 라벨을 `labelFormat`으로 만든 문자열. 라벨이 빈 문자열이면 토큰을 만들지 않는다.
- 파일명 = `[출력명, 토큰...]`을 `delimiter`로 이은 것 + `.png`.
- 금지 문자 `\ / : * ? " < > |`는 토큰과 출력명에서 `-`로 바꾼다. 앞뒤 공백은 지운다.

### 5.4 폴더

- `folder = true`인 카테고리 i마다 폴더 한 단계. 폴더명 = `[출력명, 토큰[0..i]]`을 `delimiter`로 이은 것.
- 폴더 중첩 순서는 카테고리 배열 순서와 같다. 바꿀 수 없다.
- 상대 경로 = `폴더1/폴더2/.../파일명`. 출력 폴더(`destination`) 아래에 만든다.

예: 순서 `[의상, 옷, 가슴, 보태배, 프레임]`, 옷만 `folder = true`, 라벨 형식은 의상·프레임 `{v}`, 나머지 `{c}{v}`:

```
알싸기_기본의상_옷1/알싸기_기본의상_옷1_가슴0_보태배0_3.png
```

폴더가 하나도 없으면 `D:\Project\mezzakuzza\Assets\Content\Character\Psykhe\PoseResource\알싸기\0_알싸기`처럼 flat하게 80개가 한 폴더에 놓인다. 이 폴더의 파일명 80개가 골든 테스트 데이터다 (§11.1).

### 5.5 내보내기 작업 목록

- 입력: 문서 데이터, 레이어 목록(id 포함), 배리에이션 목록.
- 출력: 작업 배열. 작업 = `{ on: [layerId], off: [layerId], relativePath }`.
- 마크가 있는 레이어만 `on`/`off`에 들어간다. 판정이 `null`인 레이어는 어디에도 안 들어간다.
- 같은 `relativePath`가 두 번 나오면 충돌. 작업 목록과 함께 충돌 목록을 돌려준다.

## 6. 패널 UI

탭 3개. 패널 상단에 현재 문서 이름과 "새로고침" 버튼. 문서가 없으면 안내만 보인다.

### 6.1 카테고리 탭

- 프리셋 드롭다운 + "적용", "현재 구성을 프리셋으로 저장", "프리셋 삭제".
- 카테고리 목록. 행마다: 색 점, 이름(편집), 라벨 형식 드롭다운, 폴더 체크, 위/아래 이동 버튼, 삭제.
- 카테고리를 펼치면 값 목록: 이름(편집), 라벨(편집), 삭제, 값 추가, "범위로 값 만들기".
- 카테고리를 지우면 그 카테고리를 참조하는 마크 항목도 지운다 (확인창). 값을 지우면 그 값을 참조하는 마크 항목만 지운다.
- 순서 이동은 위/아래 버튼으로 한다. 드래그는 넣지 않는다.

### 6.2 레이어 탭

- 문서의 레이어 트리를 위에서 아래 순서로 보여 준다. 그룹은 접을 수 있다. 행: 들여쓰기, 이름, 눈 아이콘(현재 가시성, 읽기 전용), 마크 배지들.
- 배지 = 카테고리 색 + 값 이름들 (`옷: 0,1`). 마크가 없는 행은 배지 없음.
- 포토샵에서 레이어를 선택하면 패널 행도 선택된다 (`select` 이벤트 구독). 패널 행을 클릭하면 포토샵 선택도 바뀐다. 다중 선택 가능.
- 선택한 레이어가 있으면 아래 마킹 영역이 열린다: 카테고리마다 값 체크박스 줄. 체크 = 마크 추가, 해제 = 제거. 다중 선택이면 전부에 같은 조작을 적용한다. 선택 간 값이 다르면 체크박스는 중간 상태로 보인다.
- "마크 지우기" 버튼: 선택 레이어의 마크 전부 삭제.
- `nativeColor` 옵션이 켜져 있으면 마크가 바뀔 때 레이어의 네이티브 색을 첫 번째 마크 카테고리 색으로 바꾼다. 마크가 없어지면 `none`으로 되돌린다.
- 새로고침: 레이어 목록을 다시 읽는다. 문서 전환(`documentAfterActivate`), 문서 닫힘 이벤트에서도 자동으로 다시 읽는다.
- 마크 변경은 즉시 XMP에 쓴다. 상단에 "PSD를 저장해야 마크가 파일에 남습니다" 안내를 항상 보여 준다.

### 6.3 내보내기 탭

- 출력명, 구분자, 출력 폴더(폴더 선택 버튼, `cep.fs.showOpenDialog`), 네이티브 색 옵션.
- 부분 출력: 카테고리마다 값 체크박스 (기본 전부 체크). 세션에서만 유지.
- 제외 조합 목록: 항목 추가 시 카테고리별 드롭다운(선택 안 함 가능)으로 부분 조합을 만든다. 삭제 가능. 저장된다.
- 미리보기: 배리에이션 개수, 파일 상대 경로 목록(스크롤), 충돌·경고 목록 (§9).
- "내보내기" 버튼 → 진행률(n/전체, 현재 파일명) → 완료 요약(성공 수, 실패 목록). 진행 중 "중단" 버튼.

## 7. 호스트(ExtendScript) API

`host/host.jsx`가 전역 객체 `LM`을 만든다. 모든 함수는 JSON 문자열을 받고 JSON 문자열을 돌려준다. 실패하면 `{"error":"메시지"}`.

| 함수 | 입력 | 출력 |
|---|---|---|
| `LM.getDocInfo()` | 없음 | `{name, path, width, height, saved}` 또는 `null` |
| `LM.getLayers()` | 없음 | `[{id, name, kind: "layer"\|"group", visible, depth, parentId, color}]` 위→아래 순서 |
| `LM.getSelectedLayerIds()` | 없음 | `[id]` |
| `LM.selectLayers(json)` | `[id]` | `{ok}` |
| `LM.readDocData()` | 없음 | 문서 데이터 JSON 또는 `null` |
| `LM.writeDocData(json)` | 문서 데이터 | `{ok}` |
| `LM.setLayerColor(json)` | `{id, color}` | `{ok}` |
| `LM.exportBegin(json)` | `{layerIds: [id]}` | `{ok}` — 해당 레이어의 가시성 스냅샷 저장 |
| `LM.exportOne(json)` | `{on: [id], off: [id], path}` | `{ok}` 또는 `{error}` — 폴더 생성, 가시성 설정, PNG 저장 |
| `LM.exportEnd()` | 없음 | `{ok}` — 스냅샷 복원 |

구현 규칙:

- 레이어 순회와 가시성 설정은 ActionManager로 한다 (`layerID`, `layerSection`, `show`/`hide` + `putIdentifier`). DOM(`artLayers`) 순회는 느리고 그룹 중첩 처리가 번거롭다.
- 네이티브 색 enum은 `none, red, orange, yellowColor, grain, blue, violet, gray`. 패널 색 이름과 매핑표를 둔다.
- PNG 저장은 레퍼런스 스크립트와 같은 Save for Web PNG-24 ActionManager 호출(투명 켬, 인터레이스 끔). 문서의 가로나 세로가 8192px을 넘으면 Save for Web 대신 `saveAs` + `PNGSaveOptions`(압축 6, `asCopy = true`)를 쓴다.
- `exportBegin`~`exportEnd` 사이의 문서 조작은 `suspendHistory`로 감싸 히스토리 한 항목으로 남긴다. 단 `suspendHistory`는 한 함수 호출 안에서만 동작하므로, 실제로는 `exportOne` 각각을 감싼다.
- 진행 중 패널이 중단을 누르면 패널이 더 이상 `exportOne`을 부르지 않고 `exportEnd`를 부른다.

### 7.1 이벤트

패널은 `PhotoshopRegisterEvent`로 `slct`(select)와 `documentAfterActivate`, `close`를 등록하고 `com.adobe.PhotoshopJSONCallback<extensionId>` 콜백을 받는다. 이벤트가 오면 레이어 목록이나 문서 정보를 다시 읽는다. 이벤트가 너무 잦으면 200ms 디바운스.

## 8. 내보내기 실행 흐름

1. 패널이 문서 데이터를 XMP에 쓴다 (출력 설정 포함).
2. 패널이 core로 배리에이션 → 작업 목록을 만든다. 충돌이 있으면 내보내기를 막고 미리보기에 표시.
3. `exportBegin({layerIds: 마크된 전체 id})`.
4. 작업마다 `exportOne(...)`을 순서대로 호출한다. 콜백을 받은 뒤 다음을 호출한다 (직렬). 결과를 모아 진행률을 갱신한다. 실패해도 계속한다.
5. 모두 끝나거나 중단되면 `exportEnd()`.
6. 요약 표시. 실패 목록은 경로 + 메시지.

## 9. 오류와 경고

| 상황 | 처리 |
|---|---|
| 마크의 layerId가 문서에 없음 | 레이어 탭 상단에 "고아 마크 n개" + "정리" 버튼. 내보내기에는 영향 없음 (작업에 안 들어감) |
| 마크가 현재 없는 카테고리·값을 참조 | 해당 레이어 배지를 회색 취소선으로 표시. 판정에서는 무시 |
| 두 배리에이션의 출력 경로가 같음 | 미리보기에 충돌 목록. 내보내기 버튼 비활성 |
| 마크된 레이어의 부모 그룹이 마크 없이 꺼져 있음 | 미리보기 경고 (그 레이어는 어떤 배리에이션에서도 안 보임). 내보내기는 허용 |
| 출력 폴더가 없음 | 만든다. 만들기 실패면 시작 전에 오류 표시 |
| 개별 PNG 저장 실패 | 그 작업만 실패로 기록, 계속 진행 |
| 문서가 저장된 적 없음(untitled) | 마킹·내보내기 모두 허용. XMP는 저장 시에만 남는다는 안내 |
| 프리셋 파일이 깨짐 | 빈 프리셋 목록으로 시작, 오류 표시. 덮어쓰지 않고 `presets.json.bak`으로 옮긴 뒤 새로 만든다 |
| 호스트가 `{error}`를 돌려줌 | 패널 하단 상태줄에 메시지 |

## 11. 검증 전략

사용자가 중간중간 직접 확인하기 어렵다. 그래서 개발자(에이전트)가 포토샵을 열어 보지 않고도 검증할 수 있는 수단을 코드와 함께 만든다. 각 plan 태스크는 아래 수단 중 하나 이상으로 끝난다.

### 11.1 core 단위 테스트 (자동)

- `core/*.js`는 DOM·CEP·포토샵에 의존하지 않는 ES 모듈. `node --test test/unit/`으로 돌린다.
- 골든 테스트: `알싸기` 폴더의 실제 파일명 80개를 `test/golden/alssagi.txt`에 넣고, 같은 카테고리 구성으로 core가 만든 파일명 목록과 일치해야 한다.
- 규칙 §5 전부에 테스트가 있다. 빈 라벨 생략, 제외 목록, 부분 출력, 충돌 감지, 고아 카테고리 무시 포함.

### 11.2 호스트 E2E (자동, 포토샵 COM)

- 이 PC의 포토샵 2020은 COM `Photoshop.Application.DoJavaScript`로 외부에서 ExtendScript를 실행할 수 있다 (2026-09-15 확인, 포토샵이 꺼져 있으면 자동으로 뜬다).
- `tools/ps-eval.ps1 -Script <jsx> [-Call <식>]`: `host.jsx`를 `$.evalFile`로 읽은 뒤 식을 실행하고 문자열 결과를 돌려준다.
- `test/fixture/make-fixture.jsx`: 테스트용 PSD를 만든다. 캔버스 240×160, 카테고리 A(값 2개)·B(값 3개)·N(1..2) = 배리에이션 12개. (카테고리, 값)마다 레이어 하나, 레이어는 고유한 단색 사각형이 격자 칸 하나를 채운다. 그룹 1개(자식 2개), 마크 없는 꺼진 레이어 1개, 마크 없는 켜진 배경 레이어 1개. `LM.writeDocData`로 문서 데이터를 넣고 `test/out/fixture.psd`로 저장한다.
- `test/e2e/export.test.js`: (1) fixture 생성 (2) `LM.exportBegin/One/End`를 core가 만든 작업 목록대로 호출 (3) 출력 파일 목록이 기대와 같은지 (4) PNG마다 `pngjs`로 열어 격자 칸 중앙 픽셀을 검사한다. 켜져야 할 레이어 칸은 그 색, 꺼져야 할 칸은 투명, 마크 없는 꺼진 레이어 칸은 투명, 배경 칸은 배경색. (5) 끝난 뒤 fixture의 가시성이 시작 전과 같은지 (`LM.getLayers`).
- `LM.readDocData`가 `writeDocData` 직후와 PSD를 닫고 다시 연 뒤 모두 같은 JSON을 돌려주는지 검사한다 (XMP 저장 확인).
- 네이티브 색: `setLayerColor` 뒤 `getLayers().color`가 바뀌는지.

### 11.3 패널 UI 검증 (반자동, DevTools 프로토콜)

- 저장소 루트의 `.debug` 파일에 포트(8092)를 적으면 CEP가 패널을 Chrome DevTools 프로토콜로 연다.
- `tools/panel.js`: `chrome-remote-interface`(Chrome DevTools 프로토콜 클라이언트. CEF 63과 호환)로 `http://localhost:8092`에 붙어 (a) 스크린샷을 `test/out/shots/<label>.png`로 저장 (b) 지정한 DOM 조작(클릭, 입력)을 실행 (c) DOM 상태를 JSON으로 돌려준다.
- 에이전트는 스크린샷을 직접 읽어 배치·색·글자 잘림을 확인하고 고친다. UI 태스크마다 "스크린샷 찍어 확인" 단계가 있다.
- UI 시나리오 테스트 `test/e2e/panel.test.js`: fixture PSD를 열고 → 카테고리 탭에서 프리셋 적용 → 레이어 탭에서 레이어 클릭·값 체크 → `LM.readDocData`(COM)로 마크가 XMP에 들어갔는지 확인 → 내보내기 탭 미리보기 개수가 12인지 확인.
- DevTools 연결이 안 되는 경우의 대체: `tools/screenshot.ps1`로 화면 전체를 찍는다. 포토샵 창이 보이는 상태여야 한다.

### 11.4 설치 검증

- `install.ps1` 실행 뒤 레지스트리 값·정션 존재를 스크립트가 확인한다.
