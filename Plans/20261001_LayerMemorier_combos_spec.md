# LayerMemorier 조합 중심 마킹 spec

작성 2026-10-01. 기반 spec은 `Plans/V 20260915_LayerMemorier_spec.md` (이하 "기존 spec"). 이 문서는 바뀌는 부분만 적는다. 적지 않은 부분은 기존 spec 그대로다.

## 0. 한 줄 요약

마크 단위를 "레이어 → 카테고리 값"에서 "조합(A0_B2 등) → 그 조합에서 켜질 레이어 목록"으로 바꾼다. 레이어 탭은 상단에 고정된 조합 선택 영역과, 그 아래 따로 스크롤되는 트리(행마다 체크박스)로 다시 만든다. 포토샵 레이어 색은 더 이상 건드리지 않는다.

## 1. 배경

0.1.1을 써 본 사용자 피드백 (2026-10-01):

- 레이어 탭 아래쪽의 카테고리별 체크박스 영역은 레이어가 많아지면 쓸 수 없다. 레이어를 하나씩 골라 아래로 내려가 체크해야 한다.
- 원 기획(`기획.txt` "'카테고리 조합'을 기억하여 매번 쉽게 배리에이션을 마크")의 의도는 **배리에이션(조합)별로** 켜질 레이어를 기억하는 것이었다. "A0 따로, B2 따로"가 아니라 "A0_B2에 들어갈 것"을 알아야 한다.
- 기존 구조도 A:0과 B:2를 같이 체크하면 "A0이면서 B2"로 동작하지만, 화면이 카테고리별 배지로 나뉘어 그렇게 보이지 않는다. 또 "A0_B2와 A1_B0에서만 켜기"처럼 직사각형이 아닌 조합 집합은 표현할 수 없다.
- 포토샵 네이티브 레이어 색은 바꾸지 않기를 원한다.
- 조합 선택이 늘어나는 만큼 패널을 더 크게 키울 수 있어야 하고, 조합 선택 영역은 트리와 분리되어 항상 보여야 한다.

## 2. 결정 요약 (사용자 확인)

| 질문 | 결정 |
|---|---|
| 조합을 고를 때 카테고리를 전부 정해야 하나 | 일부만. 정하지 않은 카테고리는 "전체" |
| 주 조작 방식 | 상단에서 조합을 고르고 트리 행의 체크박스로 넣고 뺀다. 우클릭 메뉴는 만들지 않는다 |
| 더 넓은 조합에서 켜지는 레이어 | 흐리게 표시만. 그 자리에서 끌 수 없고(예외 저장 없음), 클릭하면 그 넓은 조합으로 이동 |
| 포토샵 캔버스 미리보기 | 켜기/끄기 토글. 끄면 켜기 전 가시성으로 되돌린다 |
| 저장 방식 | 조합 항목 목록 (`combos`) |
| 네이티브 레이어 색 | 기능 삭제 |

## 3. 용어 (기존 spec §2에 추가·변경)

| 용어 | 뜻 | 예 |
|---|---|---|
| 조합 | 카테고리 일부에 값을 하나씩 정한 것. 정하지 않은 카테고리는 전체 | `A0_B2` (N은 전체) |
| 조합 항목 | 조합 하나 + 그 조합에서 켜질 레이어 목록. 문서 데이터에 저장되는 단위 | `{when: {A:0, B:2}, layers: [101, 102]}` |
| 관리 레이어 | 어느 조합 항목에든 들어 있는 레이어. 내보낼 때 켜거나 끈다 | |
| 마크 | 더 이상 쓰지 않는 말. 화면 문구는 "조합"으로 바꾼다 | |

배리에이션(모든 카테고리 값을 정한 것)의 뜻은 그대로다. 배리에이션은 조합의 특수한 경우다.

## 4. 데이터 모델

### 4.1 문서 데이터 version 2

```json
{
  "version": 2,
  "baseName": "알싸기",
  "delimiter": "_",
  "destination": "D:/export/알싸기",
  "categories": [ ...기존과 같음... ],
  "combos": [
    { "when": { "c_9f3a": "v_1a2b", "c_77aa": "v_00ff" }, "layers": [1234, 1290] },
    { "when": { "c_9f3a": "v_1a2b" }, "layers": [1301] }
  ],
  "excluded": [ ...기존과 같음... ]
}
```

- `marks`, `nativeColor` 필드는 없어진다.
- `when`: `{카테고리 id: 값 id}`. 키가 없는 카테고리는 전체. `{}`는 "모든 조합"이다.
- `layers`: 포토샵 layerID(숫자) 배열. 중복 없음. 순서는 의미 없다.
- 같은 `when`(키 집합과 값이 모두 같음)을 가진 항목은 하나만 있다.
- `layers`가 빈 항목은 저장하지 않는다 (마지막 레이어를 빼면 항목째 지운다).

### 4.2 version 1 변환

`readDocData` 결과의 `version`이 1이면 패널이 메모리에서 바로 version 2로 바꾼다. XMP에는 다음 저장 때 version 2로 쓰인다. 변환은 순수 함수(`LMCore.combos.migrate`)로 한다.

- 레이어 마크 `{카테고리: 값 집합}`마다 값 집합들의 데카르트 곱을 만들고, 각 조합을 `when`으로 하는 항목에 그 레이어를 넣는다. 예: `{A: [0,1], B: [2]}` → `A0_B2`, `A1_B2`.
- 같은 `when`이 여러 레이어에서 나오면 한 항목으로 합친다.
- 현재 카테고리 목록에 없는 카테고리 키는 버린다 (기존 판정도 무시했다). 남은 키가 없으면 그 마크는 버린다.
- 카테고리에 없는 값 id는 집합에서 뺀다. 그래서 값 집합이 비면 그 마크는 버린다 (기존 판정에서 "항상 꺼짐"이었지만 새 모델에는 "관리하되 어디서도 안 켜짐"이 없다).
- 버린 마크의 레이어 수를 돌려주고, 0이 아니면 패널 상태줄에 "변환하면서 레이어 n개의 마크를 버렸습니다 (없는 카테고리·값 참조)"를 띄운다.
- `nativeColor`는 버린다. `marks`도 지운다.

변환 의미 보존: 위 규칙을 지킨 마크는 모든 배리에이션에서 기존 `visibility.judge`와 같은 켜짐/꺼짐/안 건드림을 낸다. 단위 테스트로 고정한다 (§8.1).

## 5. 규칙 (core 로직)

새 파일 `core/combos.js` (UMD, `LMCore.combos`). `core/visibility.js`는 지운다 (판정이 `combos`로 옮겨 감).

### 5.1 조합 일치

- `matches(when, variation)`: `when`의 모든 키 k에 대해 `variation[k] === when[k]`이면 true. `{}`는 항상 true.
- 없는 카테고리·값을 가리키는 키는 배리에이션 값과 같아질 수 없으므로 그 항목은 어떤 배리에이션과도 맞지 않는다. 따로 처리하지 않는다.

### 5.2 배리에이션의 켜짐/꺼짐

- 켬 = `matches`가 true인 모든 항목의 `layers` 합집합 중 문서에 있는 것.
- 끔 = 문서에 있는 관리 레이어 − 켬.
- 관리 레이어가 아니면 어디에도 들어가지 않는다 (안 건드림, 기존 결정 유지).
- 그룹 레이어도 같은 규칙. 그룹이 꺼지면 자식은 포토샵 동작대로 안 보인다.

### 5.3 패널에서 쓰는 조합 판정

선택한 조합 `S`와 레이어 `L`에 대해:

- `checked`: `when`이 `S`와 정확히 같은 항목에 `L`이 있음.
- `inherited`: `checked`가 아니고, `when`이 `S`의 진부분집합인 항목(더 넓은 조합) 중 `L`이 있는 것이 있음. 그런 항목이 여럿이면 키가 가장 많은 것(가장 좁은 것), 같으면 `combos` 배열 순서가 앞인 것을 대표로 돌려준다 (클릭 시 이동할 곳).
- `none`: 둘 다 아님.

`S`보다 좁은 조합(예: `S`=A0, 항목 A0_B2)에만 있는 레이어는 `none`이다. 그런 관계는 행 오른쪽의 조합 이름 목록으로 보인다 (§6.2).

### 5.4 조합 편집

- `toggle(combos, when, layerIds, on)`: 새 배열을 돌려준다. `on`이면 `when` 항목(없으면 만든다)에 레이어를 넣고, 아니면 뺀다. 비면 항목을 지운다.
- `removeLayers(combos, layerIds)`: 모든 항목에서 뺀다. 빈 항목은 지운다.
- `removeFor(combos, categoryId, valueId|null)`: `when[categoryId]`가 있는(값 지정 시 그 값인) 항목을 지운다. `countFor`는 지울 항목 수.
- `orphanLayerIds(combos, layers)`: 항목에 있으나 문서에 없는 레이어 id. `pruneOrphans`로 지운다.
- `managedLayerIds(combos, layers)`: 문서에 있는 관리 레이어 id (오름차순). `exportBegin`에 넘긴다.

### 5.5 이름과 정렬

- `comboName(when, categories)`: 카테고리 배열 순서대로 `카테고리 이름 + 값 이름`을 `_`로 이은 것. 예 `A0_B2`. `{}`면 `모든 조합`. 없는 카테고리·값은 그 자리에 `?`.
- "만든 조합" 목록 정렬: 카테고리 배열 순서대로, 각 카테고리에서 "전체"가 먼저, 그다음 값 배열 순서.

### 5.6 미리보기 배리에이션

- `previewVariation(when, categories)`: `when`에 없는 카테고리는 그 카테고리의 첫 값으로 채운 배리에이션. 값이 0개인 카테고리가 있으면 null (미리보기 불가, 안내 표시).

### 5.7 내보내기 작업 목록 (기존 spec §5.5 변경)

- `buildJobs(docData, layers, variations)`의 on/off 계산을 §5.2로 바꾼다. 나머지(경로, 충돌)는 그대로.
- 경고:
  - `orphan`: 항목에 있으나 문서에 없는 레이어 (레이어마다 1개).
  - `stale`: 없는 카테고리·값을 가리키는 항목 (항목마다 1개).
  - `parentHidden`: 관리 레이어의 조상 중 관리 레이어가 아닌 꺼진 그룹이 있음 (기존과 같음).

## 6. 패널 UI

### 6.1 패널 크기

- `CSXS/manifest.xml` Geometry: 기본 `520×760`, 최소 `320×300`(그대로), 최대 `2000×3000` 추가.
- 버전을 `0.2.0`으로 올린다 (데이터 형식이 바뀜).

### 6.2 레이어 탭

```
┌ 고정 영역 (스크롤 안 됨) ─────────────────────────┐
│ 조합  [A: 0 ▾] [B: 2 ▾] [N: 전체 ▾]               │
│ 만든 조합 [A0_B2 · 3개 ▾]   [☑ 포토샵 미리보기]    │
│         A0_B2_N1로 표시 중                         │
│ 선택 2개  [선택 레이어를 모든 조합에서 빼기]        │
│ 고아 2개 [정리]   PSD를 저장해야 조합이 남습니다    │
├ 트리 (여기만 스크롤) ──────────────────────────────┤
│ [☑] 👁 A0                    A0_B2, A1            │
│ [▣] 👁 셔츠                  A0                   │
│ [ ] 👁 B0                    B0                   │
│ ▾ [ ] 👁 G                                        │
│     [☑] 👁 GA                A0_B2                │
│ [ ]  ·  H                                         │
└───────────────────────────────────────────────────┘
```

배치:

- 레이어 탭은 `main` 높이를 꽉 채우는 세로 flex. 고정 영역은 내용 높이만큼, 트리는 남은 높이를 차지하고 `overflow: auto`. 레이어 탭에서는 `main` 자체가 스크롤되지 않는다. 다른 두 탭은 지금처럼 `main`이 스크롤된다.
- 다시 그릴 때 트리의 스크롤 위치를 유지한다 (기존 `main.scrollTop` 복원을 트리에도 적용).

고정 영역:

- 조합 선택: 카테고리마다 `<select>` 하나. 첫 항목 `전체`, 그다음 값 이름. 앞에 카테고리 색 점. 폭이 모자라면 줄바꿈 (`flex-wrap`). 선택은 세션 상태(`LMState.combo`, 저장 안 함). 문서가 바뀌면 `{}`로 초기화.
- 만든 조합: `<select>`. 항목마다 `이름 · n개`(문서에 있는 레이어 수). 지금 선택이 만든 조합이 아니면 맨 위에 `(새 조합)`이 선택된 상태. 고르면 조합 선택이 그 `when`으로 바뀐다.
- 포토샵 미리보기 체크박스와 상태 글(§6.3).
- 선택 n개 + "선택 레이어를 모든 조합에서 빼기" 버튼. 선택이 없으면 이 줄을 숨긴다. 누르면 확인창 "레이어 n개를 조합 m개에서 뺍니다. 계속할까요?" (m = 영향받는 항목 수). m이 0이면 버튼 비활성.
- 고아 레이어가 있으면 "문서에 없는 레이어 n개가 조합에 남아 있습니다 [정리]".
- 카테고리가 0개면 고정 영역 대신 "카테고리 탭에서 카테고리를 먼저 만드세요." 한 줄.

트리 행 (왼쪽부터):

- 들여쓰기, 그룹 접기 화살표, 체크박스, 눈 아이콘(현재 가시성, 읽기 전용), 이름, 오른쪽 흐린 글씨로 이 레이어가 들어간 조합 이름들(§5.5 정렬, `, `로 연결, 넘치면 말줄임, 전체 목록은 `title`).
- 체크박스 상태 = §5.3. `checked`는 체크, `inherited`는 흐린 체크 모양(☑과 구분되는 스타일, 예: 반투명 + 테두리 점선)과 `title="A0에서 켜짐 (클릭하면 이동)"`, `none`은 빈 칸.
- 카테고리 색 배지는 없앤다.

조작:

- 체크박스 클릭 (`checked`/`none`): 대상 = 클릭한 행이 선택에 들어 있으면 선택된 레이어 전부, 아니면 그 행 하나. 클릭 후 상태가 체크면 `toggle(..., on=true)`, 아니면 `on=false`. 선택은 바꾸지 않는다. 저장 → 다시 그림 → 미리보기 켜져 있으면 반영.
  - 다중 대상일 때 기준 상태는 클릭한 행의 상태다 (클릭한 행이 `none`이면 전부 넣기, `checked`면 전부 빼기).
- 체크박스 클릭 (`inherited`): 조합 선택을 대표 항목의 `when`으로 바꾼다. 데이터는 바꾸지 않는다.
- 행 클릭 (체크박스·화살표 밖): 선택. Ctrl = 하나 토글, Shift = 마지막으로 클릭한 행(앵커)부터 이 행까지 보이는 행 범위로 선택을 바꿈. 포토샵 선택도 같이 바꾼다 (기존 동작, 메아리 무시 포함).
- 아래쪽 마킹 영역과 "마크 지우기" 버튼은 없앤다.

### 6.3 포토샵 미리보기

- 켜면: 그 시점 문서의 전체 레이어 가시성(`getLayers().visible`)을 스냅샷으로 기억하고, 바로 한 번 반영한다.
- 반영: `previewVariation(LMState.combo)`로 배리에이션을 만들고 §5.2로 on/off를 계산해 `LM.applyVisibility({on, off})`를 부른다. 반영한 레이어 id를 "건드린 레이어" 집합에 더한다. 상태 글 = `A0_B2_N1로 표시 중`(전체 카테고리를 채운 이름). null이면 `값이 없는 카테고리가 있어 미리보기를 할 수 없습니다`.
- 켜져 있는 동안 조합 선택이 바뀌거나 체크박스로 조합이 바뀌면 다시 반영한다.
- 끄면: 건드린 레이어만 스냅샷 값으로 되돌린다 (`applyVisibility`). 미리보기 중 손으로 바꾼 관리 레이어 눈도 되돌아간다. 관리 레이어가 아닌 레이어는 미리보기가 건드리지 않았으므로 손으로 바꾼 상태가 남는다.
- 스냅샷은 문서별(`docKey`)로 `LMState.previews`에 둔다. 다른 문서로 넘어갔다 돌아오면 토글은 켜진 상태로 보이고, 조합 선택도 캔버스에 마지막으로 반영한 조합으로 돌아오며, 끄면 복원된다. 새로고침 때 열린 문서 목록(`LM.getOpenDocKeys`)에 없는 문서의 스냅샷은 버린다.
- 패널을 닫거나 다시 읽으면 스냅샷이 사라지고 가시성은 미리보기 상태로 남는다. 상태 글 옆에 "끄면 원래대로 돌아갑니다"를 보여 사용자가 끄고 떠나게 유도한다.
- `applyVisibility`가 일으키는 `Shw `/`Hd  ` 이벤트는 패널 자신의 메아리이므로 기존 `muteEcho`로 무시한다.
- 내보내기 중에는 미리보기 반영을 하지 않는다. 내보내기는 시작 시 가시성(미리보기 상태일 수 있음)을 기억했다가 끝나면 그대로 되돌리므로 미리보기 스냅샷과 충돌하지 않는다.

### 6.4 카테고리 탭

- 카테고리 삭제 확인창(지금처럼 항상 띄움): `카테고리 "X"를 지웁니다.` 뒤에 n > 0이면 ` 이 카테고리를 쓰는 조합 n개도 지워집니다.` (n = `countFor(c, null)`).
- 값 삭제 확인창: `값 "X"을 지웁니다. 이 값을 쓰는 조합 n개도 지워집니다. 계속할까요?` n이 0이면 확인 없이 지운다 (지금과 같은 기준). 지운 뒤 상태줄 문구도 "조합 n개가 지워졌습니다"로 바꾼다.
- 프리셋 적용: 조합이 하나라도 있으면 "프리셋을 적용하면 현재 문서의 조합이 전부 지워집니다. 계속할까요?" 후 `combos = []`.
- 카테고리를 지울 때 `when`에서 그 키만 빼서 더 넓은 조합으로 합치지 않는다. A0_N1의 레이어가 A0 전체로 퍼져 의도와 달라질 수 있어서다.
- 새 카테고리를 추가하면 기존 항목의 `when`에는 그 키가 없으므로 전체로 취급된다. 따로 처리하지 않는다.

### 6.5 내보내기 탭

- "마킹할 때 포토샵 레이어 색도 바꾸기" 줄을 지운다.
- `exportBegin`에 `managedLayerIds(combos, layers)`를 넘긴다.
- 경고 문구: `parentHidden` = "조합에 넣은 레이어 X의 부모 그룹 Y가 꺼져 있어 어떤 조합에서도 안 보입니다". `stale` = "없는 카테고리·값을 쓰는 조합 X (내보내기에서 무시)". `orphan`은 기존과 같음.

## 7. 호스트 API 변경 (기존 spec §7)

| 변경 | 함수 | 입력 | 출력 |
|---|---|---|---|
| 추가 | `LM.applyVisibility(json)` | `{on: [id], off: [id]}` | `{ok}` — `suspendHistory('LayerMemorier 미리보기', ...)` 한 항목으로 가시성 설정. `_runJob`의 가시성 부분과 같은 `setVisibleMany`를 쓴다 |

`getLayers`의 `color` 필드는 그대로 둔다 (읽기만 하므로 해가 없고, 빼면 기존 테스트만 바뀐다).

포토샵 2020이 켜져 있는 개발 PC에서 에이전트가 직접 돌린다 (기존 spec §11 수단 그대로).

### 8.1 core 단위 테스트 (`npm test`)

- `test/unit/combos.test.js`:
  - `matches`: 빈 조합, 일부 키, 없는 카테고리·값 키.

  - `toggle`/`removeLayers`: 항목 생성, 중복 없음, 빈 항목 삭제, 입력 배열 불변.
  - 판정 `checked`/`inherited`/`none`, 대표 항목 고르기(가장 좁은 것, 같으면 앞).
  - `removeFor`/`countFor`, `orphanLayerIds`/`pruneOrphans`, `managedLayerIds`.
  - `comboName`, 목록 정렬, `previewVariation`(빈 카테고리 null).
  - `migrate`: 데카르트 곱, 같은 `when` 합치기, 없는 카테고리 키 버림, 없는 값 버림, 빈 마크 버림 + 버린 수, `nativeColor`/`marks` 제거.
  - **의미 보존**: 무작위 마크(시드 고정, 카테고리 3개·값 2~3개·레이어 20개, 없는 카테고리·값 참조 없음)를 만들어 모든 배리에이션에서 기존 `judge` 결과(테스트 안에 복사해 둔 참조 구현)와 변환 후 §5.2 결과가 같은지.
- `test/unit/jobs.test.js`: `combos` 기반으로 고친다. 경고 3종.
- `test/unit/visibility.test.js`는 지운다. 골든 테스트(파일명 80개)는 그대로 통과해야 한다.

### 8.2 호스트 E2E (`npm run test:e2e`, 포토샵 COM)

- fixture 문서 데이터를 version 2로 바꾼다: `test/fixture/fixture-docdata.json`의 `marksByName` → `combosByName` (`[{when, layers: [이름]}]`). 기존 마크와 같은 의미가 되게 옮긴다 (G는 `A1`, GA는 `B0` 등).
- `export.test.js`: 같은 12개 PNG, 같은 픽셀 검사가 통과해야 한다 (의미 보존을 실제 출력으로 확인).
- `host.test.js`: `setLayerColor` 테스트 삭제. `applyVisibility`가 on/off를 맞게 바꾸고 히스토리가 정확히 1칸 늘어나는지(`app.activeDocument.historyStates.length`). `getOpenDocKeys`가 열린 문서 키를 돌려주는지. version 2 문서 데이터의 XMP 왕복(닫았다 다시 열기 포함).

### 8.3 패널 E2E (`test/e2e/panel.test.js`, DevTools 프로토콜)

- 프리셋 적용, 카테고리 탭 흐름은 기존 테스트를 문구만 바꿔 유지.
- version 1 문서 데이터를 XMP에 써 둔 fixture를 열면 패널이 변환한 `combos`를 보이고, 체크 하나를 바꾼 뒤 `readDocData`가 version 2인지.
- 조합 선택 `A=0, B=2` → 트리 체크박스 상태가 §5.3과 같은지. 체크 클릭 → `readDocData().combos`에 반영. 다시 클릭 → 항목 삭제.
- `A=0` 항목에 넣은 레이어가 `A0_B2` 화면에서 `inherited`로 보이고, 클릭하면 조합 선택이 `A=0`으로 바뀌는지.
- 다중 선택(Ctrl, Shift 범위) 후 선택된 행 체크 → 선택 전부 반영. 선택 밖 행 체크 → 그 행만.
- "선택 레이어를 모든 조합에서 빼기" 확인창 문구와 결과.
- 미리보기: 켜기 → `getLayers` 가시성이 §5.2 결과와 같은지 → 조합 바꾸기 → 다시 같은지 → 끄기 → 켜기 전 스냅샷과 같은지. 관리 아닌 레이어는 손대지 않았는지.
- 고정 영역: 트리를 끝까지 스크롤한 뒤에도 조합 선택 `<select>`의 화면 위치가 그대로이고 `main.scrollTop === 0`인지.
- 내보내기 탭에 색 옵션이 없는지, 미리보기 개수 12.
- 레이어 색: 테스트 전체 동안 `getLayers().color`가 fixture 초기값에서 바뀌지 않는지.
- 스크린샷: 레이어 탭을 기본 폭과 좁은 폭(320), 넓은 폭(900)으로 찍어 줄바꿈·말줄임·겹침을 직접 확인한다. 폭은 CDP `Emulation.setDeviceMetricsOverride`로 바꾼다.

### 8.4 사용자 확인이 필요한 것

- 포토샵에서 패널 가장자리를 끌어 실제로 2000×3000 범위까지 늘어나는지 (CEP 창 크기는 자동화로 바꿀 수 없다).
- 실제 PSD에서 레이어 수백 개일 때 체크 클릭 반응 속도.

## 10. 범위 밖

- 우클릭 메뉴.
- 조합 안에서 끄는 예외(넓은 조합에서 켜진 레이어를 좁은 조합에서만 끄기).
- 포토샵 현재 가시성을 그대로 조합으로 캡처하는 기능.
- 이미 칠해진 네이티브 레이어 색 되돌리기 (도구가 칠한 색과 아티스트가 칠한 색을 구분할 수 없다).
- 레이어 이름 필터·검색 (레이어가 아주 많아지면 다음 후보).
